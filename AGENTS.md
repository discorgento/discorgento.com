# AGENTS.md

Discorgento community site (Brazilian Magento/tech community + podcast), built with **Astro 7 + Tailwind v4**. All active development happens in this repository root.

## Language rules

- **Code, comments, filenames, commit messages and docs (this file, README, etc.) must be in English.**
- **Exception — site content stays in Portuguese**: the `pt-BR` strings in `src/lib/i18n.ts` are the product itself (Brazilian community site). Never translate or "fix" them to English.
- UI copy that is hardcoded in components must be moved to `src/lib/i18n.ts` instead of being written inline.

## Commands

All commands run from the repo root.

- `npm install` — install deps
- `npm run dev` — foreground dev server (Ctrl+C to stop)
- `npm run dev:start` — start dev server in **background** (log in `.astro/dev.log`)
- `npm run dev:stop` — stop the dev server
- `npm run dev:reset` — full clean cycle in one command: stop the old server, clear `node_modules/.vite`, production-build, start a fresh server. Use it when the dev server has gone stale.
- `npm run build` — production build to `dist/` (only meaningful verification). Safe to run with the dev server up: it stops the server, clears `node_modules/.vite`, builds, and restores the server exactly as it was. As pre-build steps it also regenerates `public/img/og.jpg` and syncs any missing episode thumbnails (both best-effort — see Architecture).
- `npm run build -- --keep-server` — same, but leaves the dev server **down** on purpose
- `npm run check` (alias `typecheck`) — `astro check`; type-checks the project and templates
- `npm run lint` — `biome check`; lint + format check across the repo, no writes
- `npm run format` — `biome check --write`; applies Biome's fixes in place
- `npm test` — `node --test` over `test/**/*.test.mjs`; unit tests for the pure `src/lib` code (feed parsers, XML decoding, thumbnail URLs, i18n key parity). Needs Node ≥ 22.18 (type stripping)

`check`, `lint` and `test` are the fast gates and all run in CI before the build; `npm run build` is still the only meaningful verification of the built output.

> The tests import `src/lib` as-is. `test/setup.mjs` (preloaded via `--import`) resolves the `~/` alias, swaps `virtual:discorgento-thumb-cache` for the fixture in `test/fixtures/thumb-cache.mjs`, and adds the JSON import attribute Node requires. Only pure functions are tested — anything that fetches takes its input from a parser you can call directly (`parseFeed`, `parseSubstackFeed`).

> `build` is a wrapper (`scripts/build.mjs`), not `astro build`. Don't "simplify" it back — see the gotcha below for why the dance is necessary, and never run bare `astro build` locally while the dev server is up.

> Background mode relies on a lock file (`.astro/dev.json`). Servers started with `--ignore-lock` or via `nohup`/`setsid` are **not** tracked by `dev:stop` — kill them by port (`lsof -ti :4321`). For the rarer status/logs check there is no npm alias: run `npx astro dev status` / `npx astro dev logs`.

### Full clean cycle (tear everything down, rebuild, start fresh)

When the dev server has gone stale (env changes, odd HMR, "it works in the browser but not in the build"), reset from zero with one command, run from the repo root:

```bash
npm run dev:reset
```

It is a two-step chain, and `scripts/build.mjs` does the teardown for you:

1. `npm run build -- --keep-server` — stops the tracked dev server, clears `node_modules/.vite`, runs the full production build, and **leaves the server down** on purpose. This is the only step that compiles anything.
2. `npm run dev:start` — brings up exactly one fresh background instance. Confirm the new PID and URL with `npx astro dev status`.

`build.mjs` already calls `astro dev stop` before building, so an explicit `dev:stop` first is redundant; the `--keep-server` flag is what keeps the build from restoring the server it just stopped, which is the _opposite_ of what a reset wants. The one gap: a server started outside the lock file (via `nohup`/`setsid`) is invisible to `dev:stop` — kill it by port first with `lsof -ti :4321 | xargs -r kill`.

For an ordinary check this is **not** needed: `npm run build` alone already stops the server, clears the cache, builds, and restores it. Reach for `dev:reset` only to deliberately start over.

### Build rules (for agents)

**The only build command to run is `npm run build`, and only when explicitly asked.** Do not "help" by building preemptively — it is the sole verification in this repo, which makes it also the one command whose cost matters.

- **Run `npm run build` as-is. Never pre-stop the dev server around it.** `build` is a wrapper (`scripts/build.mjs`) that stops the dev server, clears `node_modules/.vite`, builds, then restores the server exactly as it found it. Manually running `dev:stop` / `rm -rf node_modules/.vite` / `dev:start` on top of that is redundant and easy to get wrong.
- **Never run bare `astro build` locally.** There is no npm script for it on purpose — it carries the footgun in Key gotchas.
- **Never "simplify" `build` back to `astro build`**, and never edit `scripts/build.mjs` to drop the stop/restore handling, unless the user asks. The dance exists because the failure is silent: the build passes and only the dev server breaks.
- **Use `npm run build -- --keep-server` only when the user asked for the dev server to be left down.** Otherwise you leave their environment broken. If you did use it, run `npm run dev:start` afterwards and say so.
- **Always run it from the repo root.** `scripts/build.mjs` resolves paths against the process cwd, and `plugins/thumb-cache.mjs` reads `public/img/episodes` from it. From another folder the thumbnail cache silently comes back empty and every episode falls back to the remote YouTube CDN.
- **A passing build _is_ the verification — report it and stop.** Do not follow it with extra probes, `dist/` archaeology, or a `wrangler deploy --dry-run` unless asked. If it fails, read the error instead of retrying variations.
- **Never run Wrangler**: `npx wrangler dev`, `wrangler dev`, `wrangler deploy --dry-run`, or any other workerd invocation, without explicit authorization. `wrangler dev` reads the _generated_ `dist/client/wrangler.json`, not `wrangler.jsonc`, so it silently serves the last build against the wrong config and reports misleading status codes (a working build comes back as 404 on every route). It also starts a `workerd` process that outlives the shell, holds port 8788, and hangs the session.
- **To verify output locally, use the dev server** (`npm run dev:start` + browser) or inspect `dist/client/` directly.

## Architecture / content layout

- `astro.config.mjs` — Astro config: `output: 'static'`, Cloudflare adapter (Workers), i18n (`pt-BR` default with no prefix, `en` under `/en/`, `es` under `/es/`), Tailwind via `@tailwindcss/vite`, `thumbCache()`, sitemap with hreflang alternates. The adapter is configured with `imageService: 'passthrough'` and top-level `session: false` on purpose: nothing here uses astro:assets or sessions, and the defaults would auto-provision a Cloudflare Images binding and a KV namespace on every deploy for features the Worker never calls. `security.csp` makes Astro emit the strict script/style policy as a per-page `<meta http-equiv="content-security-policy">` with hashes of the inline scripts it injects (the `server:defer` island bootstrap cannot carry a static hash — its content ends with a per-page encrypted prop payload). `public/_headers` keeps the directives that can't live in a meta tag; see the Deploy section for the split.
- **The episode catalog is the one content collection.** `src/content.config.ts` (Astro 7 Content Layer, `glob()` loaders, Zod 4 from `astro/zod`) defines four collections over one folder per episode, `src/content/episodes/<slug>/`: `episode.json` (YouTube id, number, date, duration, spoken language, localized title and chapters, host slugs from `src/lib/team.ts`, guest references), `pt-BR.md`/`en.md`/`es.md` (`episodeNotes`: meta description, key points and FAQ in the frontmatter, the summary as the body) and `transcript.json` (timestamped paragraphs in the spoken language); plus `src/content/guests/<slug>.json`. The slug is the folder name and is identical in every locale, which is what lets MainLayout derive hreflang from the path. Per-file shape is enforced by the schemas; the cross-file rules (all three locales present, a transcript per episode, known hosts, existing guests, no duplicate YouTube id) by `catalogProblems()` in `src/lib/episodes.ts`, which `getEpisodes()` runs at build and `test/episodes.test.mjs` runs against the files on disk. There is no blog.
- `src/pages/` — routes per locale, root = pt-BR, `en/` = English, `es/` = Español. Hand-written pages: `index.astro`, `podcast.astro`, `quem-faz.astro`, `privacidade.astro`, `404.astro`, and the same four under `en/` and `es/` (the 404 exists only for the default locale). The one dynamic route is `podcast/[slug].astro` (also under `en/` and `es/`): a thin wrapper that renders `EpisodePage.astro` for each catalogued episode — the watch page (real youtube-nocookie iframe right under the h1, because Google only gives video results on a page whose main purpose is one video; `?t=<seconds>` seeks it), with summary, key points, Q&A, chapters, people, transcript and `PodcastEpisode` + `VideoObject` (+ `Clip` per chapter) + `BreadcrumbList` JSON-LD from `buildEpisodeJsonLd()`. `llms.txt.ts` and `llms-full.txt.ts` are prerendered endpoints generated from the catalog (`src/lib/llms.ts`). `podcast.xml.ts` is the on-demand RSS feed (not a page). Its items link to the episode pages, but each `guid` stays the YouTube URL so readers don't re-announce the archive. It lists the episodes and is **not** a podcast-directory feed: there is no audio `<enclosure>`, so Spotify/Apple will not ingest it. The audio lives on the Spotify show; don't add iTunes tags without an audio source.
- `src/layouts/MainLayout.astro` — the only layout: html shell, skip link, navbar, footer, and all SEO (canonical, hreflang, Open Graph, Twitter card, JSON-LD `WebSite` + `Organization` in one `@graph`).
- `src/components/` — `Home.astro` (the home page shell, shared by every locale: data loading, the `.zine` root and the page-wide fanzine styles — buttons, `.wrap`, section heads, scroll reveal) plus its sections in `src/components/home/` (`Masthead`, `Byline`, `Colophon`, `Contents`, `EpisodesBand`, `Newsletter`, `PullQuote`, `Team`, `Join`, `EpisodePlayer`). Each section carries its own styles written `:global(.zine) …`, because the `.zine` root belongs to Home; Home's shared rules reach into the sections with `.zine :global(…)`, `Episodes`, `Navbar`, `Footer`, `TeamPage` (the `/quem-faz/` page for both locales), `PrivacyPage` (the `/privacidade/` page for all three locales), `YouTubeStamp`, `EpisodeArt.astro` (the shared episode `<picture>`: AVIF/WebP sources + JPEG `<img>`, display:`contents` wrapper, peripheral styling kept in the parents via `:global()`), `CookieConsent.astro` (opt-in analytics consent — see the Analytics section below), `LatestEdition.astro` and `DiscordStats.astro` (server islands — see below).
- **Analytics is opt-in and hand-rolled; there is no CMP dependency.** `CookieConsent.astro` (rendered once from `MainLayout.astro`) gates Google Analytics 4 behind a non-modal consent banner. It is _Basic_ consent mode: `gtag.js` is only injected after the visitor accepts, so a decline costs zero requests. Choice lives in `localStorage` (`dg-consent`, timestamped) and expires after 180 days; accept and reject carry identical weight and nothing is pre-selected. The footer's "cookie settings" button reopens the banner, so consent can be withdrawn. All copy lives in `i18n.ts` under the `consent.*` keys; the GA measurement ID (`G-ZZCPZLMW8G`) is in the component (it is public, not a secret). A hand-written privacy page (`PrivacyPage.astro`, `/privacidade/` in every locale, `privacy.*` keys) documents the measurement and links back to the banner; the footer links to it.
- Server islands (`server:defer`) re-render **on every request** in the Worker; each takes a build-time prop for its `slot="fallback"` stand-in (swapped out once the island lands — the fallback is the same component, so one copy of the styles serves both), sets `Cache-Control: no-store` on the island response, and degrades to the fallback if its fetch fails. The set: `LatestEpisode.astro` (latest YouTube cover in the hero), `HomeEpisodes.astro` (home grid) and `Episodes.astro` (the `/podcast/` list — used as a `server:defer` island by `PodcastPage.astro`), all fetching the edge-cached YouTube feed at request time (the static fallback is the committed snapshot); `LatestEdition.astro` (Substack "última edição" card — takes `locale` as its only prop — never recover it from the `Referer` header, which browsers and privacy extensions trim; the CSS lives in `global.css` because its fallback markup is authored in `Home.astro`, not in the component itself); and `DiscordStats.astro` (Discord member/presence counters in the colophon — takes `locale` and the build-time `stats` as fallback props, then refetches the invite API at request time). Island-scoped styles need the island's own root inside the page scope — see the `.zine` wrapper pattern in the gotchas.
- `src/lib/i18n.ts` — UI strings per locale (`pt-BR`, `en`, `es`) + `useTranslations(locale)`, plus `LOCALE_META` (language-switcher labels), `stripLocale` (drop the `/en` or `/es` prefix) and `intlLocale` (`Intl` tag per locale).
- `src/lib/youtube.ts` — channel RSS fetch (`getLatestVideos`, `formatEpDate`, `thumb`); on failure it degrades to the episode catalog. `getSnapshotVideos()` is that catalog as feed-shaped videos (the build-time fallback of every episode island) and throws if the catalog is empty. `thumb()` returns a self-hosted path for ids present in `CACHED_THUMBS` and the remote `i.ytimg.com` URL otherwise.
- `plugins/thumb-cache.mjs` — Vite plugin emitting `virtual:discorgento-thumb-cache` with the ids cached under `public/img/episodes/`. Exists because page code cannot read the filesystem during prerender.
- `scripts/sync-thumbs.mjs` — runs automatically as a pre-build step inside `npm run build` (no npm alias anymore); downloads the missing episode thumbnails. Only `mqdefault` (320x180) and `maxresdefault` (1280x720) are genuinely 16:9 on YouTube — `hqdefault` (480x360) and `sddefault` (640x480) are 4:3 and lose a quarter of the frame to the 16:9 `object-fit`. So every episode gets 320 and 1280 downloaded, and the **640 and 1024 are derived** from the 1280 with sharp rather than downloaded. The 1024 exists for the cover on a phone: a 346 CSS px slot at DPR 2.625 needs 908 real px, so without it the browser jumps 640→1280 and pulls 41% more pixels than the screen can show. Each JPEG tier is then re-encoded to WebP (quality 78, effort 5), cutting the 1280 covers from 133–159 kB to 72–107 kB. Page `srcset` picks between the tiers; the WebP goes in a `<picture>` `<source>` and the JPEG stays in the `<img>` as fallback.
- `scripts/gen-og.mjs` — runs automatically as a pre-build step inside `npm run build` (no npm alias anymore); builds `public/img/og.jpg`, the 1200x630 social card. Regenerates on every build (deterministic, so it stays byte-identical); it only meaningfully changes after a palette, logo or wordmark change.
- `src/lib/substack.ts` — `getLatestSubstackPosts`, the Substack feed fetch. It runs **at request time**, not at build: it is called from the `LatestEdition` server island (see below), retries three times with backoff, edge-caches the feed via `cf.cacheTtl` (1800s), and degrades to `[]`. There is no committed snapshot — the "última edição" block is live.
- `src/lib/discord.ts` — `getDiscordStats`, Discord member/presence counts. Called from the `DiscordStats` server island at request time and from `Home.astro` at build (its fallback); fails safe to `null`.
- `src/lib/team.ts` — `team` / `getTeam`, the host roster behind `TeamPage`. A host photo is used at two sizes, so the byline asks for less. GitHub avatars are resized server-side, so `photoSrcset` rewrites `?s=400` to offer `?s=96` as well; a local photo in `public/time/` cannot be rewritten and needs a real small copy named `<slug>-96.<ext>`, which the resolver picks up. The `<slug>-96.` suffix cannot shadow the main `<slug>.` photo. Keep the small copy JPEG, not WebP — it is referenced from a bare `srcset` with no `<picture>`, so there is no fallback if a browser rejects the format.
- `src/lib/episodes.ts` — pure helpers over the catalog: paths, `toCard()` (a feed video → localized title + internal link when catalogued, YouTube link otherwise), `mergeWithCatalog()` (the 15-item feed plus the archive), durations, `buildEpisodeJsonLd()`, `catalogProblems()`. It never imports `astro:content`: the server islands and `/podcast.xml` run in the Worker, and importing the collection there would bundle every transcript into it. They read `virtual:discorgento-episode-index` instead — `plugins/episode-index.mjs`, which reads the `episode.json` files (and each locale's `description:` line) in Node, like `thumb-cache.mjs`; `astro.config.mjs` (video sitemap entries) and `scripts/sync-thumbs.mjs` use its `readEpisodeIndex()` too. `src/lib/episode-content.ts` (`getEpisodes()`) is the `astro:content` side — prerendered pages and endpoints only.
- `scripts/import-transcript.mjs` — `node scripts/import-transcript.mjs <slug> <captions.vtt> [corrections.json]` turns a YouTube caption file (fetched locally with `uvx yt-dlp`, see the header) into `transcript.json`: drops the rolling-caption repeats, groups ~45 s paragraphs, applies whole-word name fixes. Run it from the repo root.
- `src/styles/global.css` — Tailwind v4 CSS-first: `@import "tailwindcss"` + `@plugin "@tailwindcss/typography"` + `@theme` (colors `--color-brand-*`, `--color-background`, etc. — **no `tailwind.config.js`**). Also holds the component classes that aren't Tailwind utilities: `.skip-link`, `.read-progress`, `.eyebrow`.

## Key gotchas

- **Default locale is `pt-BR`, content is in Portuguese.** Keep new UI copy in Brazilian Portuguese (site content exception — see Language rules). Locale folders must match `i18n.locales` exactly (`pt-BR`, `en`, `es`).
- **Astro 7 + Tailwind v4 — do not follow old tutorials (≤ Astro 5 / Tailwind v3).** Content Layer API (`src/content.config.ts`, `glob()` loader, `z` from `astro/zod`) and CSS-first Tailwind (`@theme`, no `tailwind.config.js`) changed everything.
- **`@tailwindcss/vite` ≥ 4.2.2 is required** with Vite 8 (Astro 7). Old versions break the build.
- **Frontmatter YAML:** colons (`:`) in values break the build — quote them (e.g. `description: "texto: com dois pontos"`).
- **All three editions exist for every route** — `pt-BR` (root), `en/` and `es/`. The language switcher is derived from `LOCALES` and `LOCALE_META` in `src/lib/i18n.ts`; never hardcode a pair of locales in a component. There is no per-post translation logic because there are no posts.
- **Deps with build scripts** (`esbuild`, `workerd`) need `allowScripts` in `package.json` (already configured).
- **Imports use the `~/` alias** (defined in `tsconfig.json` → `./src/*`) — never use relative `../`/`../../`.
- **Deploy uses the adapter's generated config; build/dev use the unified package entrypoint.** Two configs, on purpose — the `main` field in `wrangler.jsonc` stays on `@astrojs/cloudflare/entrypoints/server` because the `@cloudflare/vite-plugin` running inside `astro build` validates `main` against an existing file and `dist/server/` does not exist yet during the config phase. But `wrangler deploy` resolves `main` as a file path and cannot follow a package subpath, so pointing it at the package fails with `The entry-point file at "@astrojs/cloudflare/entrypoints/server" was not found`. The adapter resolves the final deployable config at the end of the build into `dist/server/wrangler.json` (physical `entry.mjs`, `no_bundle: true`, assets `../client`) — that is what the CI passes to `wrangler deploy --config ./dist/server/wrangler.json` (staging adds `--name staging`). Same for the removed `platformProxy` adapter option: it no longer exists in v14, dev runs in workerd natively.
- **The filesystem is not readable from page code at build time.** With the Cloudflare adapter, prerendering runs inside workerd, where `process.cwd()` is `/bundle`, `import.meta.dirname` is `undefined`, and `import.meta.url` is rewritten to a site URL. Never use `existsSync` in an `.astro` file or `src/lib` to decide on-disk state — it silently always misses and you ship the fallback path. Read the disk in a Vite plugin instead (see `plugins/thumb-cache.mjs`), which runs in real Node.
- **The thumbnail tiers are derived from the filenames, not hardcoded.** `plugins/thumb-cache.mjs` matches `/^(.+)-(\d+)\.jpg$/` rather than listing `(320|640|1024|1280)`. A hardcoded alternation silently breaks when a tier is added: `webpSrcset()` goes null, and every `<source>` vanishes from the built page — which reads as a WebP regression instead of a stale regex. The sizes the site can actually request are the `ThumbSize` union in `src/lib/youtube.ts`, which is the single source of truth; an unexpected width on disk is inert.
- **`sizes` must state the slot's real width, never `100vw`.** `srcset` selection is `sizes × devicePixelRatio`, so an overestimate crosses a tier threshold and the new tier becomes unreachable while still looking correct in the markup. The cover measures 347 CSS px in a 412 px viewport — the gutter and the `object-fit` frame are not free — and `100vw` at DPR 2.625 asks for 1081 px, which skips the 1024 tier entirely and lands on 1280. Hence `84vw` on the cover and `90vw` on the podcast card. Re-measure the rendered width in the browser after changing a gutter; do not trust the arithmetic. A `sizes` value cannot be verified by watching `currentSrc` in a long-lived devtools session either — repeated `deviceScaleFactor` emulation changes leave `srcset` selection returning the largest candidate for every input, so confirm against a fresh Lighthouse run in production instead.
- **Publishing an episode: the site works with zero steps, the page takes four.** Until the catalog knows a video, the islands show it straight from the feed and link to YouTube. To give it a page: create `src/content/episodes/<slug>/` (`<nnn>-<topic>`, never renamed afterwards — it is the URL) with `episode.json`, the three `.md` files and `transcript.json` (via `scripts/import-transcript.mjs`), add a `src/content/guests/<slug>.json` per guest, then `npm test` + `npm run check`. Write the summary, key points and Q&A from the transcript, attributing opinions to who said them; never invent facts the episode does not contain — these pages exist to be quoted.
- **Thumbnails after publishing: nothing to run.** `npm run build` syncs the new cover into `public/img/episodes/` automatically (the skip-if-present guard keeps it cheap), and the freshly generated files ship inside `dist/client` — so the self-hosted thumb arrives with the next deploy, no manual step. The site does not depend on it though: `thumb()` in `src/lib/youtube.ts` falls back to the YouTube CDN for any id missing from the cache, and uncommitted synced files still end up in the build because they land in `public/` before Astro copies it.
- **Never run bare `astro build` while the background dev server is running.** `npm run build` handles this for you (stop → clear `node_modules/.vite` → build → restore); only the raw form still carries the footgun. Root cause: dev server and build share `node_modules/.vite`, and the Cloudflare adapter's SSR dep-optimizer cache (`deps_ssr`) is re-optimized by the build. The running workerd runner then points at a deleted `@astrojs_cloudflare_entrypoints_server.js?v=<hash>` and every request returns 500 ("The file does not exist at … which is in the optimize deps directory"), while the production build itself still passes.
- `wrangler.toml` (local, legacy) and `.wrangler/` are in `.gitignore` — they may contain sensitive account_id/IDs. Versioned configs are `wrangler.jsonc` (production — the source of truth the adapter merges at build) and `wrangler.staging.jsonc` (staging mirror with a different worker name) — both without secrets. If one exists locally, delete `wrangler.toml` so it doesn't conflict with the versioned configs.

## Deploy

- **Fully automated via GitHub Actions** — `.github/workflows/deploy.yml`:
  - `build` job runs on every push/PR (gate: `npm run check` + `npm run lint` + `npm test` + `npm run build`). On non-PR runs it uploads `dist/` (hidden files included, for `.assetsignore`) as the `dist` artifact.
  - `deploy` job runs on push or `workflow_dispatch` on `main`, via `cloudflare/wrangler-action@v4` (`wrangler deploy --config ./dist/server/wrangler.json`) — production Worker `discorgento` (first deploy creates it; then attach the `discorgento.com` custom domain).
  - `deploy-staging` job runs on push or `workflow_dispatch` on `develop`, via `wrangler deploy --config ./dist/server/wrangler.json --name staging` — staging Worker `staging`, served at `staging.jonatanaxe.workers.dev`. Both jobs deploy the `dist` artifact from the `build` job instead of rebuilding, so what ships is exactly what passed the gates (a rebuild would re-fetch the feeds). Each environment has its own `concurrency` group, so deploys queue instead of overlapping.
  - Requires two repo secrets: `CLOUDFLARE_API_TOKEN` (scoped: Workers Scripts Edit, Workers Routes Edit) and `CLOUDFLARE_ACCOUNT_ID`. Never use a full-account token. Trigger `workflow_dispatch` for manual deploys.
- **The deploy ships a Worker, not just assets** — since the `LatestEdition` server island. `wrangler.jsonc` keeps `main` on the unified package entrypoint so `astro build` (which validates `main` before `dist/` exists) and workerd dev keep working; the deploy itself uses the config the adapter resolves at the end of the build, `dist/server/wrangler.json`, via `wrangler deploy --config ./dist/server/wrangler.json` (staging targets the `staging` Worker with `--name staging`). `compatibility_flags` are `["nodejs_compat", "global_fetch_strictly_public"]`, and the `assets.binding: ASSETS` wiring carries through into the generated config.
- **`wrangler.jsonc` is versioned** (assets pointing at `dist/client`, `not_found_handling: 404-page`, `html_handling: auto-trailing-slash`, no `account_id` inside — the action injects it via the `accountId` secret). The Worker `name` must match the existing Worker in the dashboard; a mismatch creates a duplicate Worker.
- **Cloudflare Git integration (Workers Builds) must stay disconnected** — it historically deployed alongside CI and conflicted with the GitHub Actions pipeline. CI owns the deploys now.
- **A strict CSP is deliberate, but it is now split across two places.** Scripts and styles are enforced by Astro's `security.csp` — per-page `<meta>` CSP whose `script-src`/`style-src-elem` carry SHA-256 hashes of exactly the inline scripts/styles Astro emitted (that is the only way the `server:defer` island works), plus `style-src-attr 'unsafe-inline'` for the static `style="--i:..."` attributes on the logo and dialog. `public/_headers` carries the directives a meta tag cannot express (`frame-ancestors 'none'`) and the rest of the resource policy (`img-src`, `frame-src`, `connect-src`, `font-src`, `object-src 'none'`, etc.). Because the meta is per-document, do not expect the `_headers` CSP to list script sources — that moved to Astro. `script-src` is `'self'` plus one third-party origin, `https://www.googletagmanager.com`, added via `security.csp.scriptDirective.resources` (the list replaces Astro's defaults, so `'self'` must be repeated there). That origin is the only reason the tag can load, and it still only loads after a visitor accepts — `CookieConsent.astro` never injects it otherwise. Cloudflare injects `static.cloudflareinsights.com/beacon.min.js` into every page and the policy still blocks it, so `beacon.min.js` in the console is the policy working, not a bug to fix. Web Analytics is switched off at the zone level and RUM is switched off with it.
- **Do not "fix" the beacon CSP error by whitelisting `cloudflareinsights.com`.** That beacon is unrelated to the opt-in GA4 in `CookieConsent.astro`; enabling Cloudflare Web Analytics would be a separate product decision and would mean editing the meta `script-src` _and_ the header `connect-src` (the dashboard toggle alone is not enough — a CSP-stripped beacon just makes Cloudflare report zero page views, which reads as a broken dashboard rather than a blocked script). Either change both or neither.
- **`style-src-attr 'unsafe-inline'` is scoped, not blanket.** Astro `security.csp` hash-locks the inline `<style>` elements under `style-src-elem` (all 82 kB of CSS land in each document via `build.inlineStylesheets: 'always'`, and removing the hash would blank the site) while only inline style _attributes_ fall back to `'unsafe-inline'` for the logo letter positions and the dialog. No `'unsafe-inline'` exists in `script-src` anywhere, in either the meta or the header.
- **Dependabot** (`.github/dependabot.yml`) opens weekly PRs for `npm` and `github-actions`; security updates are automatic.
- Before a deploy, validate locally (no auth needed): `npm run build && npx wrangler deploy --dry-run`.
- **Never write the literal `[skip ci]` marker in a human commit message** — GitHub skips *every* workflow for a push whose head commit carries it **anywhere in the message, body included** (learned the hard way: a body sentence quoting the workflow's marker silenced CI/CD for that whole push; the Cloudflare Git suite still appeared, because an external app does not parse it). The marker belongs only in commit messages generated by the workflows themselves, such as the Substack announcer's state commit. Spell it as "skip-ci marker" in prose.
- `public/robots.txt` already allows AI crawlers explicitly (GPTBot, ClaudeBot, PerplexityBot, etc.) — **Cloudflare blocks AI by default** ("AI Crawlers"); if you touch robots.txt, keep the `Allow` lines or the AI-ready work dies at the firewall.

## Substack → Discord announcer

- `.github/workflows/substack-discord.yml` announces new Substack posts in the community Discord news channel, hourly (cron offset from `:00` — GitHub queues top-of-hour crons first). It posts through the channel webhook, whose URL lives in the `DISCORD_WEBHOOK_URL` repo secret — never in code, the repo is public. Public repo also means the scheduled minutes are free and unlimited.
- `scripts/substack-discord.mjs` does the work: reads the feed with `fetchSubstackPosts()` (`~/lib/substack` — the same parser the LatestEdition island uses), diffs it against `.github/substack-discord-state.json` (the last announced post, committed by the workflow with `[skip ci]` so the state commit never triggers the site deploy) and posts the announcement through the channel webhook in the channel's established voice — `@everyone` header, bare link (Discord unfurls Substack's own OG card), author credit — under the site's username/avatar. The three lines rotate through variant banks in the script (`HEADER_/LINK_/CREDIT_VARIANTS`), each picked from a slice of the post-URL hash: deterministic per post (a resumed run never changes an announcement's words), and the shifts must stay unsigned (`>>>`) — a signed `>>` goes negative once the hash crosses 2³1. A real author ping needs a `<@id>` entry in `AUTHORS_DISCORD_IDS`. State is written after every successful post, so a mid-list failure resumes instead of replaying. A missing state file announces only the newest post — the bootstrap run must not dump the whole feed. Exits 0 on an unreachable feed (retries next hour), 1 on a webhook refusal. `buildAnnouncement(post)` is exported and `main()` only runs when the script is executed directly, so previews can import it without posting.
- `scripts/tilde-alias.mjs` is the Node resolve hook that maps `~/` (src/) for CLI scripts — the same mapping tsconfig/Vite give the site code — so they can import `src/lib` under plain `node --import` without a bundler. `test/setup.mjs` reuses it for `npm test`.
- Run it manually from the repo root: `DISCORD_WEBHOOK_URL=… node --import ./scripts/tilde-alias.mjs scripts/substack-discord.mjs`.
